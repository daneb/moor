# Design — moor-bundle

## Approach

A new command, `commands/bundle_cmd.rs`, with its docker arguments built by
pure functions, so the container's shape is tested without Docker (the same
approach as `posture::derive` and `compose::render`).

- `export_args(m, run) -> Vec<String>`: `run --rm -i --network none
  -v <project>-workspace:/workspace -w /workspace --entrypoint sh <image>
  -c <script> sh [run]`. The script is `cat > /tmp/moor-host-chain.jsonl &&
  keel export "$@" --chain /tmp/moor-host-chain.jsonl --out /tmp/moor-out >&2
  && cat /tmp/moor-out/*.tar.gz`. keel prints the bundle path on stdout, so
  that goes to stderr, leaving stdout as nothing but the archive. The image's
  default `agent` user owns the workspace volume, as in the sandbox (AC-1,
  AC-2).
- `verify_args(m) -> Vec<String>`: `run --rm -i --network none --entrypoint
  sh <image> -c 'cat > /tmp/b.tar.gz && keel bundle verify /tmp/b.tar.gz'`. No
  volume, because the archive is all it needs (AC-5).
- `run(name, run, out)`: load the manifest, `audit::fold_sink` so keel's
  latest `run_end` is in the chain, then write the host chain to a temp file.
  Then `proc::run_stdin_to_file(export_args, chain, archive)`. On failure it
  removes the archive and bails with keel's stderr, which streams live, so
  the operator sees it (AC-4). On success it prints the path, runs
  `run_with_stdin_file(verify_args, archive)` so keel's report prints, and
  exits with keel's exit code (AC-5). `main.rs` gains `Bundle { project,
  run, out }`, with the project resolved the way `moor keel` resolves it.
- `proc::run_stdin_to_file`: stdin from a file, stdout raw to a file,
  stderr inherited. It's binary-safe, which `run_capture` is not (AC-3).
  AC-4 is tested by a failing command (`sh -c 'printf partial; exit 1'`)
  through the same cleanup path.

**e2e (AC-6).** After the existing chain steps, it writes a minimal spec (two
`cmd` criteria) into the sandbox with `sh -c 'cat > …'`, then runs `keel gate
g0`, `approve --stage spec`, `plan`, `gate g1` and `run --no-driver`. G2's
verdict doesn't matter; the run ends and writes `run_end` either way. Then
`moor bundle` runs, and the test checks that its output shows `pass` for
`chain`, `approvals`, `gate-verdicts` and `trajectory`.

**Docs.** ARCHITECTURE and README describe `moor bundle` next to `moor audit
--export`.
