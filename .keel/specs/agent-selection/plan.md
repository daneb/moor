# Design — agent-selection

## Approach

The seam is **image resolution**: today it is a single function,
`import_cmd::detect_image(from) -> &str`, keyed only on language markers.
This change introduces an orthogonal **agent axis** and composes the two
at that one seam, leaving the language detection itself untouched.

1. **An `Agent` enum in `manifest.rs`** (`Claude` | `Copilot`), with a
   `FromStr`/parse that accepts exactly `"claude"`/`"copilot"` and errors
   otherwise (AC-5), and a default of `Claude` (AC-2). It is a new field
   on `Manifest` (`agent: Agent`), serialized to `moor.yaml`, defaulting
   to `Claude` via `#[serde(default)]` so existing manifests still load.

2. **A pure `resolve_image(language_image, agent) -> String`** (in
   `manifest.rs`, next to the enum). For `Claude` it returns the language
   image unchanged (AC-4). For `Copilot` it maps
   `moor/<lang>:latest` → `moor/copilot-<lang>:latest`, and the base image
   `moor/base:latest` → `moor/copilot:latest` (AC-3). Pure, so it is
   unit-tested without Docker — every oracle above is a `cargo test` of
   this function and the enum parse.

3. **A `--agent` flag** on `import` and `new` (`main.rs`), parsed into
   `Agent`, threaded into each command. `import_cmd`/`new_cmd` set
   `m.agent` and compute the final image as
   `resolve_image(detect_image(..)/explicit-image, agent)`. An explicit
   `--image` still wins as the *language* input to resolution (out of
   scope note in the spec), so `--image X --agent copilot` composes X with
   copilot the same way.

This keeps the change behind one pure function plus a flag: the risky
part (which image string) is fully covered by unit tests, and the wiring
(flag → manifest → resolve) is mechanical. The follow-on spec will make
`resolve_image`'s output actually buildable on demand and wire the driver
default + secrets; this spec establishes the axis and the resolution.

## Budget note

Raised from 120 to 200 lines deliberately. The production logic (the
`Agent` enum, `resolve_image`, and the flag wiring across four files) is
~60 lines; the remainder is five thorough unit tests — the oracles — in
`manifest.rs`. The churn is test coverage, not scope creep, so the budget
is raised rather than the tests thinned.
