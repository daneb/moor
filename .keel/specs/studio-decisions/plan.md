# Design — studio-decisions

## Approach

Two seams, both already present and both extended rather than replaced:
the **`Approval` state machine** in `state.rs` (which already arms and
confirms an approval) and the **`Host` trait** in `mod.rs` (which already
has `approve`).

### Rejection

`Approval` gains a rejecting variant that carries a reason buffer, so the
one state machine covers both decisions and they cannot be confused:

```
Idle --x--> Rejecting{project, slug, command, reason: String}
      type -> reason grows (Backspace shrinks it)
      Enter -> RejectArmed{..} (only if reason is non-empty)
      y     -> Action::Reject{project, slug, command, note}
      Esc   -> Idle, nothing recorded
```

- AC-1/AC-3: `x` enters reason entry; `Enter` arms; a second distinct key
  (`y`, as approval uses) confirms. Two keys, so no single press records a
  decision.
- AC-2: `Enter` on an empty reason leaves the state as it is and sets the
  status line to say a reason is required — nothing is emitted.
- AC-4: `Esc` returns to `Idle` from either rejecting state.
- AC-5: the command is keel's own, taken from the same `keel next --json`
  field `arm_approval` already reads, with `--reject --note <reason>`
  appended — never reassembled from the stage name. `Host` gains
  `reject(project, command)` beside `approve`, so `mod.rs`'s Docker impl
  runs it through the same logged `keel_cmd` path.

Keystrokes while rejecting must not reach the agent input, so
`handle_key` matches the rejecting states before the ordinary
`Key::Char` → `input.push` arm.

### Gate output

`Project` gains `failing_checks: Vec<String>`. `Host` gains
`gate_output(project, slug) -> Result<String>` reading the newest
`.keel/specs/<slug>/gates/G*.json` through the same `docker exec` read
`read_artifact` already uses. `refresh` fills `failing_checks` for a
project whose stage indicates a failed gate; `apply_next` stays the only
place stage is set, so the two cannot disagree.

- AC-6: `render::frame` lists the failing check names under the project.
- AC-7: every name goes through the existing `render::sanitize` before it
  is drawn — the same treatment agent text already gets, since gate JSON
  comes from the sandbox.

`frame` stays a pure function of `Console`, so AC-6/AC-7 are asserted on
the string it returns, with no terminal and no container. The `FakeHost`
in `mod.rs`'s tests gains the two new methods, which is how the host
boundary stays testable.

## Budget note

Raised from 400 to 520 deliberately. Production is ~270 lines (the
rejection state machine, the gate-evidence read, the parser, the render
lines) and the eight oracle tests are ~200 — 25 lines each, which is what
it takes to assert a two-key flow and that a hostile check name cannot
reach the terminal. Thinning the tests would remove the proof that the
decision is a human act, which is the point of the spec.

Noted for future specs: estimate as production + 25 per criterion + 20%
slack, rather than guessing a round number. Also noted: refactoring
existing code to reduce churn *increases* it, since churn counts changed
lines, not the resulting file size.
