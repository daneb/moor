# Design — agent-session-abstraction

## Approach

The seam is **one agent profile table** inside `session.rs`. Everything
Claude-specific today is a hardcoded constant in one of four functions;
each becomes a field looked up by `Agent`.

1. **`manifest.rs`**: add `Kiro` to the existing `Agent` enum and its
   `FromStr` (AC-1). `resolve_image` already returns a non-copilot image
   unchanged, so Kiro needs no image mapping here.

2. **`session.rs`: an `AgentProfile`** returned by `profile(Agent)` —
   a plain struct of what differs:
   - `argv_prefix`: `["claude","--print","--output-format","json"]` /
     `["copilot","-p"]` / `["kiro-cli","chat","--no-interactive"]`
   - `allow_flag` / `deny_flag`: `Some("--allowedTools")` /
     `Some("--disallowedTools")`; copilot `--allow-tool` / `--deny-tool`;
     kiro `--trust-tools` / **`None`** (AC-4)
   - `resume_flag`: `Some("--resume")` for claude/copilot, `None` for
     kiro (AC-6)
   - `output`: `Json` (claude) or `PlainText` (copilot, kiro) (AC-5)
   - `auth_hint`: the fix for that agent (AC-7)

3. **The four functions take the agent**: `build_turn_argv(agent, role,
   prompt, resume)` builds from the profile instead of literals;
   `parse_turn(agent, stdout)` reads JSON or wraps plain output as the
   response; `failure_hint(agent, project, text)` returns the profile's
   hint. `run_turn` already loads the project's `Manifest`, so it reads
   `m.agent` and threads it — **no caller signature changes**, which is
   what keeps `ask_cmd.rs`/`studio`/`recipe` out of the diff.

4. **AC-3, the safety rule**: if `role.denied_tools()` is non-empty and
   the profile's `deny_flag` is `None`, `run_turn` returns an error naming
   the agent and the role rather than building an unrestricted argv. This
   is a refusal, not a warning: ADR-0008 established that an allow-list
   alone does not restrain, so running a restricted role on kiro would be
   running it unrestricted.

5. **AC-8**: the existing `agent-turn` chain entry gains an `agent` field
   from the same value — the record already carries role and session id,
   so this is one more field on an existing struct.

The profile table is pure data and every behaviour above is a pure
function of it, so all nine oracles are unit tests with no container.

## Budget note

Raised from 320 to 480 lines deliberately. The production change is the
profile table plus four functions rewritten against it (~150 lines); the
rest is the eight oracle tests (~150) and the mechanical threading of the
agent through roughly fifteen existing test call sites, which the
signature change forces. Splitting the work would leave `session.rs`
half-converted — some turns agent-aware, some not — which is worse than a
larger single change. The churn is tests and mechanical threading, not
scope creep.

## Scope note

`cli/src/commands/ask_cmd.rs`, `studio/`, `recipe.rs`, `main.rs` and
`compose.rs` appear in the computed blast radius because they depend on
`session.rs`/`manifest.rs`. Step 3 deliberately keeps the public
signatures they call (`run_turn`, `ask`) unchanged, so none of them is
edited by this change.
