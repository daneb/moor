# Design — keel-evidence-retention

## Approach

The seam is **`.gitignore`** — which of keel's outputs are repository
content and which are local working state. No Rust changes: the decision
is entirely about what gets committed, plus the one command that produces
the thing that does.

1. **Invert the two keel entries.** `.gitignore` today ignores
   `.keel/bundles/` ("regenerated from runs by `keel export`") and tracks
   `.keel/runs/`. That is backwards relative to `keel cover`, which asks
   whether the tree is covered by a *committed, verified bundle*. So:
   - ignore `.keel/runs/` (AC-1) — local working evidence, and the thing
     whose tracking makes every run's diff contain the previous runs'
   - stop ignoring `.keel/bundles/` (AC-2) — the verified, portable
     artefact, 232K against a 1.1M raw run
   - ignore `.keel/chain.jsonl` (AC-3) — append-only and hash-linked, so
     two branches always conflict in it and resolving always discards one
     side's entries. It travels inside bundles, which is where it is
     verifiable anyway. This has already cost two merges on this branch
     and the one before it.

   `.keel/specs/` and `.keel/store/` stay tracked: small, and the record
   of what was decided rather than of a run.

2. **`make evidence`** (AC-5): `keel export` for the latest run, then
   `keel export --verify` on what it wrote, so the target fails rather
   than committing an unverifiable bundle. Sits beside the existing
   `make ci`/`make security` targets and uses the same
   check-the-tool-is-present idiom.

3. **`docs/EVIDENCE.md`** (AC-6): what is kept and why — the measured
   numbers, the quadratic cause, why a bundle is the durable artefact, the
   one-time migration command, and the upstream half (keel including
   `.keel/` in its captured diff) named as keel's to fix rather than
   silently absorbed. `docs/CI.md` gets a pointer to it, since the
   evidence story is part of what CI checks.

AC-4 and AC-7 need no new code: AC-4 verifies a bundle `keel export`
already writes, and AC-7 is the existing suite, which nothing here
touches. Every oracle is a shell command against the repository itself,
which is the right shape for a change whose subject *is* the repository's
own layout.

## Migration, deliberately outside the gate

Untracking the 464 already-committed run files is
`git rm -r --cached .keel/runs .keel/chain.jsonl`, whose diff is tens of
thousands of deleted lines of generated evidence. Gating that would
measure deletion volume rather than this decision, so it is documented in
`docs/EVIDENCE.md` and run once after this merges — with a bundle
exported first, so the evidence that mattered is committed before the raw
runs stop being.
