# Design — audit-chain-atomicity-and-agent-image

## Approach

Two independent seams, both inside existing single-responsibility functions.
No public signature changes, so the +1/+2 callers (`main.rs`, `compose.rs`,
`commands/up.rs`, `commands/mod.rs`) are unaffected — they are in the blast
radius only because they call `resolve_image`/`append_chained`, and the
contracts of both are preserved.

**Seam 1 — the chain writer and reader (`cli/src/audit.rs`).** The write
side is `append_entry`; the read side is `last_entry`. Both change, neither
grows a new caller:

- *Atomic single write (AC-1).* Build the full line — `serde_json::to_string(&entry)`
  plus a trailing `\n` — into one `String`/`Vec<u8>` and emit it with a
  single `write_all`, replacing `writeln!` (which may split into multiple
  `write` syscalls). `O_APPEND` already guarantees each `write(2)` lands at
  the current end; a single `write_all` of one buffer makes the whole line
  one such write.
- *Serialised appends (AC-2).* Take an OS advisory lock on the file for the
  read-compute-write cycle so two `moor` processes (e.g. a `ui` exec-log
  firing during another command) cannot interleave. Add `fs2` (or
  `rustix`/`libc` `flock`) — a pinned, maintained crate — and hold an
  exclusive lock from just before `last_entry` to just after the write, so
  the next-seq computation and the append are one critical section. The lock
  is advisory and process-local to moor; the sandbox never has the path, so
  this adds no new trust assumption.
- *Tolerant reader (AC-3, AC-4).* `last_entry` stops assuming one object per
  line. Parse the last non-empty line with `serde_json::Deserializer::into_iter`
  and take the final successfully-decoded `ChainEntry` on that line; if the
  whole last line is unparseable, walk backwards to the previous line rather
  than erroring. A single malformed historical line therefore degrades to
  "read the last good entry", never a hard error that stops `moor next`.
  The hash framing and `compute_hash` are untouched — the golden-entry test
  stays green.

**Seam 2 — image composition (`cli/src/manifest.rs`, `cli/src/ui/data.rs`).**

- *Refuse cross-agent composition (AC-5, AC-6).* In `resolve_image`, before
  prepending `prefix`, detect whether the image is already in *some other*
  agent's layer using the existing `image_is_copilot`/`image_is_kiro`
  predicates (generalised to "is in any agent layer other than the requested
  one"). If so, return the image unchanged — the same leave-alone branch the
  function already has for an image in its own layer. This is the minimal
  change: one more guard clause in the one function that composes names.
- *Reject the mismatch at the edit (AC-7).* In `ui::data::update_manifest`,
  when an image patch names an image in a different agent layer than the
  manifest's resolved `agent()`, `bail!` with a message naming the mismatch
  instead of saving it — mirroring the existing `valid_image` bail.

**ADR (AC-8).** Add `docs/decisions/0016-atomic-audit-chain-and-image-guard.md`
recording the atomic+serialised append, the tolerant reader, and the
cross-agent refusal. It extends ADR-0013 (agent reconciled from image),
which established that the image is the source of truth for the agent.

All new behaviour is unit-tested at the function boundary with real files
and real `resolve_image` inputs — no mock stands in for the behaviour under
test (conventions: a test that mocks away the behaviour is worse than none).
