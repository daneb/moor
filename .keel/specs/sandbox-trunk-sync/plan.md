# Design — sandbox-trunk-sync

## Approach

The seam is the boundary ADR-0014 already established: credentialed git
runs on the host, and the result crosses into the sandbox only as a
`git bundle` streamed through `docker exec`. `moor sync` reuses that exact
machinery rather than inventing a new path — `pull_cmd.rs` already has
`https_github_url`, `fetch_argv`, and the host-fetch → bundle → stream-in
sequence, and `mod.rs` already has `host_github_token`, `run_git_as_host`,
and `stream_into_sandbox`. The one new idea is what happens *after* the
bundle is inside the sandbox.

`moor pull` ends with `git merge --ff-only FETCH_HEAD` on the checked-out
branch — the step that disturbs an in-progress feature. `moor sync` instead
resolves trunk (the upstream's branch, e.g. `origin/master` → `master`,
same resolution `doctor` already does) and:

- When trunk is **not** HEAD: `git update-ref refs/heads/<trunk>
  FETCH_HEAD` — advance the trunk ref only, touching no working-tree file,
  no index, no HEAD. This is the whole point: the feature branch and its
  uncommitted `.keel/` state are never read or written.
- When trunk **is** HEAD: fall back to `merge --ff-only`, but only after
  `git status --porcelain` reports 0 entries; a dirty trunk refuses and
  changes nothing.

A new `sync_cmd.rs` holds this, wired as `Command::Sync` in `main.rs`
beside `Pull`/`Doctor`. The reusable pieces in `pull_cmd.rs`
(`https_github_url`, `fetch_argv`, the host-fetch helper) are made
`pub(crate)` so `sync_cmd` shares them rather than copying; `pull_cmd`'s
own behaviour is unchanged.

For doctor (AC-7/8): `git_state` today reads `--porcelain=v2 --branch`,
whose behind-count reflects only the last fetch. The fix is a host-side
`git fetch origin <trunk>` (same host-credential path, no sandbox
credential) that updates the local `refs/remotes/origin/<trunk>` before
the status read, so the count is truthful; and the behind-advice line is
changed from `moor pull` to `moor sync`.

## What this reuses, verbatim

- `pull_cmd::https_github_url`, `pull_cmd::fetch_argv` — URL rewrite + host
  fetch argv (promoted to `pub(crate)`).
- `mod::host_github_token`, `mod::run_git_as_host`, `mod::stream_into_sandbox`
  — credential resolution, host git with token, bundle stream-in.
- `doctor_cmd::parse_porcelain_v2`, trunk resolution from the upstream.

`sync_cmd.rs` and a new `Command::Sync` arm — plus two bounded edits

`moor doctor` to their prior behaviour; no data migration, no state on
disk changes shape.
