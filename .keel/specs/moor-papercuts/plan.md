# Design — moor-papercuts

## Approach

**Identity (AC-1, AC-2).** The seam is `compose::render`, which already turns
the manifest into the sandbox's environment.
- `render_with(m, identity: &[(&str, String)])` is pure. It renders a new
  `{{GIT_CONFIG_ENV_LINES}}` placeholder into `GIT_CONFIG_COUNT: "n"` plus a
  `GIT_CONFIG_KEY_i` and `GIT_CONFIG_VALUE_i` pair for each entry. Values are
  quoted, with `\` and `"` escaped for YAML and `$` doubled for compose.
- `render(m)` reads `git config --get user.name` and `user.email` on the host,
  keeping whichever are set, and calls `render_with`.
- The placeholder goes in the template's sandbox `environment:` block, after
  the secrets, and joins the list the existing no-placeholder-survives test
  checks.
- `sync_git_identity` stays, so `new_cmd.rs` and `import_cmd.rs` stay out of
  scope. It is harmless, because environment config takes precedence over the
  repo-local config it writes for imports.

**e2e (AC-3).** After the existing pipeline approves `e2e-bundle` in a
`moor new` project, it reads `.keel/specs/e2e-bundle/approvals.jsonl` inside
the sandbox and checks its `by` is the host's `git config user.name`. When the
host has no identity, as on CI runners, it passes with a note that there was
nothing to compare.

**Image (AC-4).** In `images/base/Dockerfile`, the `keel-build` stage gains
`ARG KEEL_VERSION=0.9.0` and runs `cargo install keel-harness --version
"$KEEL_VERSION" --locked`, which makes the version part of the layer's cache
key. `images/build.sh` forwards `KEEL_VERSION` from the environment when it is
set. Docs: IMAGES.md says how to bump it.
