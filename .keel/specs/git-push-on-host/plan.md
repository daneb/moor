# Design — git-push-on-host

## Approach

**The seam: a single host-side git helper, replacing four in-container
credential-helper call sites.** Today each credentialed operation
(`ship` push, `new` clone, `import` clone, `pull`) runs `git -c
credential.helper='…$GITHUB_TOKEN…'` *inside* the sandbox via `docker
exec`. The change introduces one host-side module — call it
`githost` — that runs git on the host with the host's own credential
(the same credential `gh pr create` already uses), and moves each of the
four sites onto it. The sandbox keeps only token-free local git.

Transport in each direction reuses the proven `docker exec` stream
pattern from `import_cmd::import_history` (which already documents why
`docker cp` fails against the read-only rootfs):

- **Out (ship):** the sandbox still makes the commit (local, no token;
  ADR-0007 authorship untouched). `githost` runs `docker exec <c> git
  bundle create - <branch>` and reads the bundle from stdout into an
  ephemeral host scratch dir, fetches the branch from it, and runs `git
  push` on the host. No standing host clone (Option A).
- **In (new / import clone, pull):** `githost` fetches on the host with
  the host credential, writes a bundle to a host temp file, and streams
  it into the sandbox via `docker exec -i <c> sh -c 'cat >
  /tmp/x.bundle'` — exactly as `import_history` does today — then the
  sandbox fetches/clones from that local bundle (no credential needed
  in-container).

`compose.rs` stops rendering `GITHUB_TOKEN`, and `manifest.rs` stops
declaring it as a sandbox secret, so it is never in the container env.
`COPILOT_GITHUB_TOKEN` is left as-is — it authenticates the Copilot
*agent*, is read by that agent's own CLI, and is out of scope here (named
in Out of scope). The fail-loud credential check (AC-6) lives in
`githost` and is called before `ship` creates a branch.

The host-side push re-emits the same `push` audit entry
(`audit::log_exec_with(.., "push", .., push_data{ref, commit})`) that
`run_cmd` produces today, so traceability does not regress. The +1
dependents (`mod.rs`, `main.rs`, `secrets.rs`, `keel_cmd.rs`, `up.rs`)
are callers and wiring; they compile against the moved functions but hold
no credential logic themselves.
